Question 1:
Look at the confidences in /tmp/fossbot-text-to-cmd/outputs/sklearn_multilingual.json.
Almost every input ended up with the same prediction and the same confidence
value (around 0.25). Explain why this happens.

Answer 1:
TF-IDF is a purely lexical representation that only recognizes words present
in the training vocabulary (built from training_commands.csv). Because the
multilingual test commands (Polish, German, Spanish) contain words never seen
during training, their TF-IDF representations become all-zero vectors with no
informative features. In the absence of feature signals, Logistic Regression
falls back entirely on its learned class bias intercept term. The class with
the highest bias intercept (which was "backward" under random_state=42) wins
every tie by default with a low probability roughly equal to class balance (~0.23-0.25).


Question 2:
Look at the templates dictionary in /tmp/fossbot-text-to-cmd/src/classifier_st.py.
There are only 3 English phrases per action - no Polish, German or Spanish.
Why is the sentence-transformer classifier still able to handle multilingual
input correctly?

Answer 2:
The underlying model (paraphrase-multilingual-MiniLM-L12-v2) was pretrained on
massive cross-lingual corpora covering ~50 languages. During pretraining, it
learned to project semantically equivalent sentences into nearby coordinates
in a shared dense embedding space regardless of language. Thus, "do przodu",
"fahre vorwärts", and "go forward" all map to nearly identical vector
representations. Cosine similarity compares this underlying semantic meaning
rather than exact character tokens.


Question 3:
The wheels field in the JSON output uses values in [-1.0, 1.0]. The mapping
from action name to wheel speeds is defined in
/tmp/fossbot-text-to-cmd/src/wheel_mapping.py. What would you change there
to make the robot turn faster on the spot?

Answer 3:
In src/wheel_mapping.py, increase the absolute magnitude of the speed values
in the WHEEL_COMMANDS dictionary for turning actions closer to the extreme limits
($\pm 1.0$). For example, change:
    "turn_left":  [-0.3, 0.3]  ->  [-0.8, 0.8]
    "turn_right": [0.3, -0.3]  ->  [0.8, -0.8]


Question 4:
The sklearn pipeline is trained from scratch on 75 examples; the
sentence-transformer model is loaded already trained. List one advantage
and one disadvantage of each approach for a project that needs to
recognise 50 different commands instead of 5.

Answer 4:
- sklearn (TF-IDF + Logistic Regression):
  * Advantage: Extremely lightweight, highly deterministic, and provides
    sub-millisecond inference latency with virtually no memory footprint (<1 MB).
  * Disadvantage: Poor scalability with respect to data collection. Recognizing
    50 commands would require manually collecting, labeling, and maintaining
    hundreds of training examples per class across every supported language, and
    it remains brittle to unseen synonyms.
- Sentence Transformers:
  * Advantage: Excellent zero-shot scalability and multilingual capability out
    of the box. Adding a new command only requires defining 2-3 template
    reference phrases without annotating an entire dataset.
  * Disadvantage: High computational and resource overhead (~100 ms CPU latency
    per query, heavy dependencies, and hundreds of MB of model weights), making
    it harder to deploy on resource-constrained embedded robotics hardware.
